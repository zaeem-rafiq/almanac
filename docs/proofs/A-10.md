Both controls caught real bugs in the checker before they caught anything in the README:
`\b\d{4}-\d{2}-\d{2}\b` did not match `2026-09-08` inside `2026-09-08T01:53:14+00:00`, and the
README's U+2212 minus made `-2.17%` read as `+2.17` so it could not ground against `judge.py`.
Without the controls both checks would have passed vacuously.

### Scope stated rather than glossed

* The issue's line is "appears in `evals/results.json` or `judge.py` constants". The check grounds
  against nine artifacts — `evals/results.json`, `evals/reproducibility.json`, `almanac/judge.py`,
  `almanac/catalog.py`, `almanac/extract.py`, `facts/catalog.yaml`, `facts/rates.json`,
  `reports/latest.json`, `requirements.txt` — because the README correctly quotes catalog values
  and `MANUAL_MAX_AGE_DAYS` too. `--verbose` names the grounding file for every number.
* Two numbers are exempt and the script prints the reason for each: `60` ("Try it in 60 seconds",
  a title) and `8000` (the uvicorn port in the run instructions).
* Numbers inside the verbatim block are grounded by the byte-equality check, not re-parsed.
* `markdown-link-check` is not installed here and installing it means an npm download, so the link
  check implements the same contract in-process: local targets must exist, `http(s)` targets must
  answer < 400. The proof line says "link check", not the tool name.

# A-06 (HAC-42) — Walkthrough: seeding a real channel and reading it back

**Status: NOT closed.** Three of four proofs are in scope and run live; the fourth is
deferred with its reason recorded in `docs/proofs/A-06.md`. See "What is left" at the bottom.

## What this issue is for

Almanac's claim is that it reads a finance creator's *actual back catalogue*. Up to A-05 that
catalogue is `corpus/channel/` — five synthetic videos as files on disk. A-06 makes the same
five videos exist on a real YouTube channel and proves Almanac can read them back through the
official API, so a judge can click from the review page to a real, public, playable video
instead of taking the corpus on faith.

The code added here is **read-only**. `videos.update` is not called anywhere in this issue.

## The shape of the work, and why it split the way it did

Five uploads have to go through YouTube Studio by hand. The Data API forces
`privacyStatus: private` on `videos.insert` from an app that has not passed Google's OAuth
verification, and ours is in Testing mode. A private video defeats the entire point — a judge
cannot open it. So the uploads are Zaeem's ~25 minutes of serial human wall-clock.

That set the ordering. `scripts/render_slides.py` and `scripts/seed_channel.md` were built
and handed over **first**, before any of the ingest code, so his clock and the build clock ran
in parallel rather than end to end.

## The renderer, and the constraint that shaped it

`scripts/render_slides.py` turns each corpus video into a 30-second slideshow: a title card
plus three bullet cards. No brand assets, no likeness of any real person — flat typographic
cards generated from the corpus text.

The obvious implementation is ffmpeg's `drawtext`. It is not available here. This machine's
ffmpeg 8.1.1 is compiled **without libfreetype and without libass**, so neither `drawtext` nor
`subtitles` exists, and nothing else that draws text is installed either — no ImageMagick, no
`rsvg-convert`, no PIL, no cairosvg. No new dependency may be added without approval.

The way through was to notice that a PDF renderer is a typesetter that is always present, and
that the base-14 fonts (Helvetica among them) are built into every one of them, so nothing has
to be embedded or installed. Each card is written out as a hand-built one-page PDF, rasterised
by macOS `sips`, and ffmpeg is asked only to do the job it can still do — sequence stills into
H.264:

    card text -> PDF (base-14 Helvetica) -> sips -> PNG 1280x720 -> ffmpeg -> MP4

Line breaking needs real font metrics, so the script carries the Helvetica and Helvetica-Bold
advance-width tables. Without them the wrap is guesswork and long titles run off the card.

Bullet selection is **deterministic code, not a model call**. Almanac's standing rule is that
only `extract.py` and `notes.py` may call a model, and picking three sentences is not worth a
model call anyway. The script takes sentences containing a numeral — Almanac exists to check
numbers, so a card with no number is a wasted card — and samples them across the runtime so
the bullets span the video instead of clustering in the intro.

### The 30-second version was wrong, and nothing in the renderer could tell

The first build produced 30s videos and verified them as such. What it never checked was the
thing that mattered: the corpus caption files run **159-168s**. Every video would have shipped
hiding ~80% of its own subtitles, cutting off mid-sentence, and the renderer would have
reported success — its assertion was "20 ≤ duration ≤ 60", which is a bound the defect
satisfied perfectly. A check can only catch what it compares against, and this one compared
the video against a constant instead of against its own caption track.

The fix, on Zaeem's call, is to synthesize narration with the macOS built-in `say` and let each
video run to the length of its own captions. `say` is text-to-speech, not a recording — no
human time, no new dependency, and the PDF → `sips` → PNG card pipeline is untouched. This
deliberately overrides the issue's "20-60s" guidance; that bound existed to keep rendering
cheap, not because 30s was correct.

Alignment is structural rather than hoped for. Each cue is spoken as its own `say` segment and
laid into that cue's own slot on the timeline, so speech begins exactly where its subtitle
begins; where speech overruns its slot it is sped up with `atempo`, where it is short the slot
is padded. Synthesising the whole script in one call would have been simpler and would have
drifted apart from the fixed caption timings within a few sentences. The bullet cards are
scheduled the same way — each appears when the narration actually reaches its sentence.

Two assertions now run on every render, and both earned their place immediately:

* **Duration against the caption track**, not against a constant. It failed on its first run:
  the concat demuxer's mandatory trailing image repeat *inherits the preceding `duration`*,
  appending a phantom 51s (212.8s of video against 161.8s of captions). Output length is now
  pinned with `-t`.
* **`mean_volume > -50 dB`**. The 30s build's audio measured **-91.0 dB** — the `anullsrc`
  signature. A silent track that merely exists is what shipped last time.

## Seeding the channel: what "manual" actually turned out to mean

The plan treated the five uploads as irreducibly manual, because an unverified OAuth app cannot
publish public videos. That is true, and it is confirmed live rather than assumed —
`videos.insert` uploads happily and the result is forced to `privacyStatus: private`, with a
`public` request simply ignored.

But "cannot publish" is not "cannot upload", and the plan had quietly collapsed the two. Asked
why the work could not be automated, the honest answer turned out to be that most of it could:

* Computer use cannot drive a browser at all — browsers are granted read-only, so clicks and
  typing are blocked. Claude-in-Chrome is the right tool for a web app, but no browser was
  connected to drive.
* `videos.insert` plus `captions.insert` does everything except the visibility flip.

So `scripts/seed_uploads.py` uploads all five privately with their caption tracks attached, and
the human step shrinks from ~25 minutes of uploading, metadata entry and subtitle attachment to
about two minutes of toggling visibility. Titles and descriptions now go up by API rather than
being retyped, which also removes the transcription risk the title-matching mapper was written
to survive.

The script is an explicit exception to the project rule *"Nothing else mutates YouTube"*, taken
with Zaeem's approval and for his own throwaway test channel only. Because it is an exception it
carries the **same triple guard** the rule demands of `videos.update` — `ALMANAC_WRITE=true`,
the channel id must equal `ALMANAC_TEST_CHANNEL_ID`, and `--apply` — rather than a weaker one.
Default is a dry run. It is idempotent: a title already on the channel is skipped, so a re-run
cannot produce duplicates.

`status.containsSyntheticMedia` is set true. The narration is text-to-speech, the field is real
(checked in the `VideoStatus` schema), and disclosing it is the honest choice for a corpus whose
whole purpose is to demonstrate checking claims honestly.

## The quota table was wrong, and everything still passed

The ledger originally priced every `.list` call at 1 unit. `captions.list` costs **50** — the
captions resource is expensive across the board, and pricing a family of endpoints by their
verb rather than by name understated a full scan by 245 units: **1008 reported against a real
1253**.

Both numbers pass the 1,500 budget, so nothing failed and nothing looked wrong. That is exactly
what makes it worth recording — the proof was passing against a figure that was not true, and
the only way it surfaced was checking the published cost table instead of carrying an
assumption forward. `QuotaLedger` now holds an explicit per-endpoint table, an unpriced endpoint
costs 1 rather than 0, and the values are pinned by a test.

## The ingest module

`almanac/youtube.py`, signatures taken as given from ADR-000 §3 (discovery revision 20260820)
rather than re-derived:

- `list_channel_videos()` — `channels.list(mine=true)` → uploads playlist id →
  `playlistItems.list` → `videos.list`. Both list calls paginate. Five videos will never need
  a second page, but a back catalogue is exactly the thing that outgrows 50 items, and a
  silently truncated catalogue means silently missing verdicts.
- `download_captions(video_id) -> str` — `captions.list(part, videoId)` then
  `captions.download(id, tfmt)`. ADR-000 records `supportsMediaDownload: True`, so
  `.execute()` returns **bytes**; decoding them is the function's job, not the caller's.

Three decisions worth naming:

**The channel guard sits on the read path.** The project rule names every channel other than
`ALMANAC_TEST_CHANNEL_ID` as protected. That guard is usually discussed as a write-side
concern, but reading the wrong channel is still the wrong channel, so `authorised_channel()`
raises rather than proceeding. A-07's write guard will sit on top of this, not replace it.

**Machine transcription is never used.** `captions.list` returns ASR tracks alongside uploaded
ones. Almanac reads numbers off these captions and decides whether a creator's figure is
stale; a misheard "twenty-three thousand" would become a fabricated claim attributed to the
creator. Uploaded tracks only.

**Missing captions are polled, not failed.** Studio attaches a caption track asynchronously,
often minutes after publish. `wait_for_caption_track` retries, because "not ready yet" and
"broken" are different things and only one of them is a failure.

## The interface that keeps A-04 unblocked

The deferred proof compares `scan --source youtube` against `scan --source corpus`. To make
that a comparison A-04 can simply run, both readers return the same record:

    Source(source_id, title, published_at, description, text, locators, origin)

`locators` is a tuple of `Cue(index, start_s, end_s, text)`, which is what lets a verdict point
at "this sentence, at 04:12" rather than at the video as a whole. `iter_sources(origin)` is the
single entry point `scan` calls. `Source` and `Cue` live in `youtube.py` only because
`almanac/models.py` belonged to a session running in parallel; A-04 is free to lift them out.

`test_corpus_and_youtube_sources_are_the_same_shape` holds that promise offline, today, so the
interface cannot quietly drift before A-04 arrives.

## Two bugs the tests caught before the live run

**The fidelity comparator could not fail.** The first version tokenised the raw SRT, so cue
indices and timestamps counted as words. Identical on both sides, they padded the denominator
with guaranteed matches: a caption with 3% of its real words rewritten scored **1.4%** and
passed the 2% threshold. It was the adversarial control — required by the A-02 lesson that a
negative assertion proves nothing until shown to fail — that surfaced it. The comparator now
parses the SRT and compares caption body only: control 3.37% red, casing-only 0%,
re-segmented cues 0%.

**The proof's placeholder check was being satisfied by accident.** A real YouTube id is
exactly 11 characters; the test fixtures minted 10-character ones, so the "is this still a
placeholder?" check was failing for the wrong reason and would have masked a genuine failure.

Both are the same lesson in different clothes: a check you have not watched fail is not
evidence.

## Quota

Counted by `QuotaLedger`, not estimated. Call counts are observed; unit costs are documented
(YouTube's quota table — the discovery document carries no cost metadata).

    channels.list 1 + playlistItems.list 1 + videos.list 1 + captions.list 5x1
    + captions.download 5x200  =  1008 units, against a 1500 budget and a 10,000/day quota.

## Results

All three in-scope proofs PASS against the live channel:

    PROOF A-06: list_channel_videos returns 5 ids matching corpus meta.json = PASS
    PROOF A-06: download_captions(V1) parses with srt lib and word-diff vs corpus < 2% = PASS
    PROOF A-06: quota used for the full scan < 1,500 units = PASS

Caption round-trip is **0.0000% word difference on all five videos**, against a threshold whose
adversarial control scored 3.37% red. ADR-000 gap **G-2 is closed**: `tfmt="srt"` was accepted
on the first attempt, so the fallback candidates were never reached.

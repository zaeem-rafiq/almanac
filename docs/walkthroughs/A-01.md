# Walkthrough — A-01 · Facts catalog + rates table + freshness tests (HAC-37)

**Status: DONE.** All five PROOF lines PASS. 25/25 tests green.

## What exists now

`facts/catalog.yaml` holds 15 entities — 11 human-approved statutory limits and 4 market rates.
`facts/rates.json` is refreshed from four primary feeds. `catalog.current(key)` is the single
resolution point every later module reasons through, and it annotates staleness without ever
suppressing a value.

```bash
venv/bin/python -m almanac facts            # 15 keys, values, dates, sources
venv/bin/python -m almanac rates --refresh  # the ONLY network path for rates
venv/bin/pytest tests/ -q                   # 25 passed
```

## The two substantive departures from the issue text

**1. Rates come from the primary feeds, not FMP.** HAC-37 §6 pre-authorised this and it turned
out to be necessary, not optional: FMP's `economic-indicators` returns a ~9-month-stale window on
our key (and ignores `from_date`/`to_date`), and returns only **2 CPI rows two months apart** —
so `cpi_yoy`, which needs observations 12 months apart, was not computable from it at all. The
four keyless feeds are current and two of them match the issue's own 9/7 figures exactly where FMP
does not. `fetched_via` names the real fetcher rather than a hardcoded `"fmp"`; writing `"fmp"`
while reading NY Fed would be a false provenance claim in the file whose whole purpose is
provenance. Full detail: ADR-000 §9.

**2. `ss_wage_base` is sourced from IRS, not SSA.** `ssa.gov` blanket-403s scripted clients — 16
paths tried including `/robots.txt`, so it is a host-level block, not a path problem. IRS Pub 15
states both figures and serves 200. The Project Rules list irs.gov as an acceptable source, so this
is in-spec; if SSA is ever wanted as the canonical link, the url-200 test would need a different
arrangement rather than a weakened assertion.

## How the 11 manual values were sourced

The agent filled nothing from memory. Each figure was fetched from a page that returned HTTP 200
to a scripted client, quoted verbatim, independently re-fetched by a second agent, and approved by
Zaeem before transcription. Three things that discipline caught:

- The standard-deduction URL originally supplied returns 200 but is the **interactive assistant**
  and contains no dollar figures at all. A 200 that cannot source the number is exactly the trap a
  url-200 test alone would not catch. The fetcher rejected it and went to Rev. Proc. 2025-32.
- The 2025 standard deduction is the **OBBBA-revised** amount (Rev. Proc. 2025-32 §2.08), not the
  originally-published 2025 figure. A back-catalog video quoting the pre-revision number is a
  judgment call for A-03, not an error here.
- `gift_annual_exclusion` is 19,000 in **both** years — the one row where the columns match, and
  it is correct.

## Four defects the adversarial review caught before they shipped

A 15-agent review raised 10 findings; 4 survived refutation, all real:

| impact | defect |
|---|---|
| wrong-verdict | `current()` treated `effective_to` as an *exemption* from the age check rather than an *expiry*, so a 2025 limit with `effective_to: 2025-12-31` resolved as the live 2026 fact with `stale=False` — Almanac's own failure mode, in its ground truth |
| crash | BLS emits `M13` (annual average); `"M13" > "M12"` as a string, so every January `date(y, 13, 1)` raised |
| weak-test | both network-isolation guards were *proven* evadable via `requests.Session` and `urllib` |
| silent-failure | the "reads rates.json" test passed with `facts/rates.json` deleted |

Each fix has a regression test, and each was verified by reproducing the reviewer's own evasion and
confirming the test now fails on it.

## Carried into A-03

- `history` is populated for all 11 manual keys but `current()` deliberately does not consult it —
  `current()` answers "what is true now". A-03's "was this true when the video was published?" is
  the question `history` exists for.
- `cpi_yoy` reads **stale** most of each month: BLS dates CPI by reference month, releases it
  mid-following-month, and the issue's `max_age_days` for CPI is 45. On 2026-09-07 the July figure
  is 68 days old. Options are to raise CPI to ~75, date `as_of` at release rather than reference
  month, or accept the flag. Left at the spec's 45 pending Zaeem's call.
- `ibond_composite_rate` uses six-month windows (2026-05-01 → 2026-10-31), not tax years.

## The principle, as mechanism rather than intention

`extract.py` is one of two modules allowed to call a model, so this is where "the LLM reads, the
code decides" either holds or quietly stops holding. It is enforced in four places:

**1. The model is never asked for provenance.** `ExtractedClaim` — the tool schema — has seven
fields: `quote, claim_type, entity_key, value, unit, year_hint, confidence`. `source_id` and
`locator` are absent. The code assigns them from the offset the quote was found at. A field the
model cannot fill is a field it cannot get wrong, and `test_the_model_is_never_asked_for_provenance`
pins the schema to exactly that set.

**2. The catalog is a gate, not a suggestion.** The model *proposes* an `entity_key`; the code
*admits* it. `_admit_entity_key()` checks it against `load_catalog().keys()` read at runtime, and
anything else — an invented key, a near-miss, a wrong case — becomes `None` while the claim itself
survives. The demotion is counted, not silent.

**3. The quote is verbatim by construction.** `locate()` normalises whitespace runs and curly
quotes on both sides while keeping an index map back to the original string, finds the quote, and
then slices the **original** text. So the stored `quote` is the source file's own bytes; `claim.quote
in text` is true because of how it was built, not because something asserted it afterwards. A quote
that does not resolve is dropped and counted — across three live runs, **0 of 175 claims** failed
this check.

That normalisation is the only leniency, and it is bounded on purpose. Whitespace and smart quotes
differ between what a model echoes and what a caption file holds; an invented sentence does not.
A similarity ratio would have let a hallucinated quote through, which is the single thing this
check exists to catch.

**4. The prompt carries no verdict vocabulary — and a test enforces it.**
`test_system_prompt_contains_no_verdict_vocabulary` fails the build if `stale`, `correct`,
`material`, `wrong`, `out of date`, `accurate`, `verdict` (and nine more) appear in the rendered
prompt. **It fired on the first run**: the draft prompt said "do not correct grammar" and "null is
a correct and common answer". Neither was a verdict about a number, but the guard is deliberately
blunt, so the prompt was reworded rather than the test loosened. The check is cheap and it now
protects every future edit to that prompt.

## Chunking, and what "locators preserved" actually means

Sources flatten into one document plus `Locator(start, end, label)` spans. SRT cues join with a
**single space** — not a choice, a constraint: the labelled quotes in `evals/claims.jsonl` cross cue
boundaries ("you can defer twenty three thousand dollars of your own money into your 401k" spans
three cues), so any other join makes the entire A-02 label set unfindable. There is a regression
test for exactly that, and it asserts all 54 rows were checked rather than only that no failure was
seen.

Chunks are cut **on locator boundaries** at ~2,000 tokens, each carrying its base offset. A quote
found at chunk-local offset `i` sits at global `base + i`, which selects the locator exactly. Cutting
mid-cue would produce chunks whose offsets no longer line up with the document — the locator lookup
would still return *something*, just the wrong thing.

`extract_sources()` flattens chunks from *every* source into one
`ThreadPoolExecutor(max_workers=4)`. The cap is on total in-flight requests, so the five-video run is
four calls in flight rather than five sequential ones. That is what turns ~14s/video into 17s total.

## The two traps A-00 and A-01 already paid for

**A negative assertion proves nothing on its own.** Proof 2 says "V4 yields 0 claims of the three
judged types" — which an extractor returning `[]` would satisfy perfectly. So proof 2 also asserts
V4 returned claims at all (19), and that the same run produced those types *elsewhere* (11 claims
across the other videos). A broken labeller now fails this proof instead of passing it.

**Assert the size of what you checked.** A-01 shipped a URL check that keyed its collection
per-entry instead of per-row and skipped 2 of 29 URLs while still reporting PASS. Proof 4 therefore
counts: `entity_key checked 61/61`, `quote checked 61/61`, and asserts both equal the claim total
and that the total is non-zero. A claim that never got checked can no longer look identical to one
that passed.

## One change made on evidence: framing beats subject matter

The first live run labelled *"Say you are in the twenty two percent bracket"* as `tax_bracket`.
`evals/claims.jsonl` labels it `illustrative`, and A-02's reading is right — the issue's own
three-way example ("say you contribute $23,000" → illustrative) says the framing decides, not the
subject. The prompt listed `tax_bracket` before `illustrative` without saying which wins, so an
explicit precedence rule was added:

> Framing beats subject matter, always. […] Ask first "is the speaker asserting this, or supposing
> it, or remembering it", and only then ask what the number is about.

After the change `tax_bracket` correctly stops firing on V1, and all four proofs still PASS.

## Findings for Zaeem — reported, not fixed

`facts/catalog.yaml`, `evals/claims.jsonl` and `corpus/**` are protected. Each of these is a
disagreement between A-02's labels and A-03's spec. None was edited by the agent's own judgement;

**F-1 · `structural` is not in the A-03 vocabulary.** Four rows in `evals/claims.jsonl` carry
`expected_claim_type: "structural"` ("You cannot touch the money for twelve months", "it resets on
the first of May and the first of November", "If you cash out before five years you give up three
months of interest", "Non medical withdrawals before sixty five get taxed and penalized"). The
`claim_type` vocabulary HAC-39 specifies is
`statutory_limit|tax_bracket|market_rate|illustrative|historical|other`. These four land as `other`,
which is the right A-03 behaviour and accounts for 4 of the 7 `claim_type` disagreements above.
**Decision needed:** either `structural` joins the vocabulary (a `models.py` change, and `models.py`
is protected after this issue), or A-04 treats `structural` and `other` as equivalent when scoring.

**F-2 · RESOLVED by Zaeem 2026-09-07 — a `historical` claim does carry its `entity_key`.**
The single `entity_key` disagreement was "Back in 2022 it paid nine point six two percent": A-02
labelled it `None`, the extractor said `ibond_composite_rate`. Zaeem's call: the key stays, and the
eval row was updated on his instruction — the one edit to a protected file in this issue, made
because he directed it.

```diff
- {"source": ".../v5-...", "quote": "Back in 2022 it paid nine point six two percent",
-  "expected_claim_type": "historical", "expected_entity_key": null, "expected_status": "skip"}
+ {"source": ".../v5-...", "quote": "Back in 2022 it paid nine point six two percent",
+  "expected_claim_type": "historical", "expected_entity_key": "ibond_composite_rate", "expected_status": "skip"}
```

`expected_status` stays `skip` — the sentence is a historically accurate statement and must not
draw an update note. What changes is *why* it is skipped: A-04 can now skip it because a rule
resolved it against the entity's history, rather than because there was nothing to resolve.

`tests/test_corpus.py:104` asserts `expected_entity_key` is `None` for every **V4** row only, so
this V5 row is outside it and no test expectation had to move. Full suite: **78 passed**.
`scripts/proof_a03.py` reads `corpus/**` and `facts/catalog.yaml` and never reads
`evals/claims.jsonl`, so the four A-03 proofs are untouched by this edit.

**F-2a · The follow-on gap, which needs Zaeem and cannot be fixed by the agent.** F-2's rationale
is that the key lets `judge.py` resolve a historical claim against `catalog.yaml`'s `history` rows.
For this claim that lookup currently finds nothing — `ibond_composite_rate` carries exactly two
history rows:

| value | effective_from | effective_to |
|---|---|---|
| 3.98 | 2025-05-01 | 2025-10-31 |
| 3.11 | 2024-11-01 | 2025-04-30 |

**There is no row covering 2022**, so a `year_hint=2022` lookup returns no covering window even
though 9.62% is the real May-2022 composite rate. Two consequences for A-04, and the first one is
a correctness trap:

1. `judge.py` **must not** read "no covering history row" as "the creator was wrong". Doing so
   turns a historically accurate sentence into a false stale verdict — precisely the failure mode
   Almanac exists to avoid. Absence of a history row is `unresolved`, never a contradiction.
2. If the 2022 window should be checkable rather than merely skipped, `facts/catalog.yaml` needs a
   history row for it. Per the Project Rules the agent may scaffold an entry with `value: null` but
   may not fill a value — that row has to come from Zaeem with a treasurydirect.gov URL. It was
   **not** added here.

**F-3 · Three `illustrative` rows land as `other`.** "Fifteen years of extra payments applied to the
wrong bucket", "you can pull that money out of the account tax free in twenty years", "Whatever is
left goes into three funds. Not thirty. Three." These are durations and counts inside hypotheticals
rather than invented dollar amounts, so `other` is defensible. Low stakes — all three carry

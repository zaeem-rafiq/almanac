That decision overrides the issue text, so the branch was replayed onto his commit and this
walkthrough describes the **port**, not the original. Dropped without argument: my `judge.py`, my
`models.py` extension, ADR-001, and my `tests/test_judge.py`. His judge is the judge.

His R1 is better than the one that was dropped. Mine skipped every `historical` claim
unconditionally. His resolves it against the catalog's **history window**: "back in 2022 it paid
nine point six two percent" is checked against the 2022 window, found genuinely right, and skipped —
while a historical claim that misquotes its own era comes back `unresolved`
(`R1.historical_disputed`). That is a capability the dropped version did not have, and it is the
guard that stops R5 firing a confident false correction on the loudest divergence in the corpus.

## Where the note lives, and why not on the Verdict

`judge.Verdict` is a frozen dataclass with no `note` field, and it stays that way. A note is prose
*about* a decision, not part of one — so `notes.annotate()` returns
`{(source_id, locator): (note, note_source)}` and `report.to_row()` performs the join.

That shape is what makes it structurally impossible for `notes.py` to change a status. It cannot
mutate a frozen dataclass, it is never handed a status to set, and it returns a different type
entirely. `tests/test_report.py::test_a_verdict_carries_no_note_field` pins it.

## The code assertion, which is the whole point of notes.py

`notes.py` is the module where the discipline is easiest to lose, because it does call a model. It
is handed a **finished** verdict — status set, `rule_fired` populated — and asked for one sentence.
`check_note()` then refuses that sentence if it drops the current value, drops the effective year,
runs past 280 characters, or contains an advice verb. The prompt asks; the code enforces.

`format_value()` defines the required string **once**, and it is used both to interpolate into the
prompt and to judge the answer. Two definitions would make the assertion decorative.

Two rejected attempts fall back to a deterministic template, which is itself passed through
`check_note()` before it ships — "correct by construction" is a claim, and the assertion is the
proof. `note_source` records `model` or `fallback` so a run where the model would not comply is
visible in the artifact rather than indistinguishable from one where it did.

`test_the_prompt_carries_the_finished_verdict_and_asks_no_question_about_it` asserts the system
prompt contains no verdict vocabulary as whole words, so the model is never invited to re-litigate
what the rules decided.

## The rule numbering changed, and the proofs say so instead of pretending otherwise

The issue text numbers the rules with R1 = skip and R4 = exact-match. `609af65` renumbers them: R1
resolves a historical claim against its window, R2 skips the unjudged claim types, R4 is the exact
match, and **a statutory limit that differs fires `R5.stale_material`, not R4**.

So `scripts/proof_a04.py` asserts the **status** each proof line specifies — which is stable across
both numberings — and prints the rule that actually fired, rather than asserting a rule number that
no longer means what the issue meant by it. Asserting `R4` against this judge would have been
checking nothing. The constants `SKIP_RULES` and `DIVERGENCE_RULE` at the top of the harness carry
that mapping with the reason.

Proof 3's "per R5" clause re-derives the expected band from **his** `MARKET_RATE_MATERIAL_PP`
rather than hardcoding today's answer, so it checks the rubric rather than restating the outcome.

## What survived from the original branch, and why

* **Proof 4's control.** It is a pure negative assertion — `extract.py` contains no verdict
  vocabulary — and A-01 shipped that bug twice. The harness runs the same grep against `judge.py`
  **first** and fails if that control does not go red, then points it at `extract.py`, and also
  asserts `extract.py` exists. A grep at a typo'd path returns nothing exactly like a clean one.
* **Proof 2's size assertion.** It prints the count of `stale_material` verdicts and asserts it is
  non-zero *before* asserting the property over them, so "all 0 of them passed" cannot pass.
* **Delta rounding in the report.** `6.85 - 6.71` is `0.13999999999999968` in binary float.
  `to_row` rounds it, so the artifact reads `+0.14`. `test_to_row_rounds_the_delta_for_the_artifact`
  fails if an unrounded float leaks into a published report.
* **The unescaped-rule test.** A pipe in `rule_fired` would be escaped by the Markdown renderer and
  stop matching the verdict it came from, quietly breaking the audit trail the column exists to
  provide. His rule names carry no pipes, and the test now guards that they never start to.

## Two deviations from the issue text, both recorded rather than papered over

**Proof 3 says "2 skips"; the run produces 4.** `fresh_wrong.md` holds four numeric sentences that
are not assertions — three illustrative and one `other` — and the extractor finds all four; the eval
set labels three. Nothing was tuned. The proof asserts what is actually about the judge: exactly one
`stale_material` and it is `ira_contribution`, the mortgage verdict matching its own band, and
**every remaining verdict a skip**.

**`reports/` is gitignored.** Scan output is a build artifact. `scripts/proof_a04.py` runs
`almanac scan` itself and then reads `reports/latest.json` back from disk, so the proofs assert over
what the CLI actually wrote rather than over a committed copy. `reports/.gitkeep` stays tracked so
the directory survives a fresh clone, per A-00's layout. Verified by deleting every generated report
first and re-running from empty.

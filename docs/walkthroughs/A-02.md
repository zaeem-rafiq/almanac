## Three gaps in the issue, and how they were closed

The rule *"numbers in the scripts come from `history` values in the catalog, never invented"*
collides with the required content mix: A-01 populated exactly one `history` row per manual key
(2025) and none at all for the rates keys. Three script numbers had no sourced home. Each was
fetched from a page already cited by this project, quoted verbatim into the transcript, approved
by Zaeem, and only then transcribed — A-01's discipline, unchanged.

| key | added | evidence quoted before approval |
|---|---|---|
| `k401_employee_deferral` | 2024 → 23,000 | `Elective deferrals 24,500 23,500 23,000 22,500` under `2026 2025 2024 2023`. The 2026/2025 columns match the catalog exactly, which is what confirmed the column alignment |
| `ibond_composite_rate` | Nov-24 window → 3.11 | row `11/24 - 04/25  1.20%  4.56%  4.34%  4.08%  3.11%` under `May-26 Nov-25 May-25 Nov-24`. The same reading produced the catalog's existing 4.26 and 3.98 |
| `mortgage_30y_fixed` | week of 2025-06-05 → 6.85 | PMMS_history.csv June 2025: `6/5=6.85, 6/12=6.84, 6/18=6.81, 6/26=6.77` |

**Two of the three were independently confirmed while this issue was in flight.** Zaeem landed
`37d1e87 feat: add 2024 history rows for k401_employee_deferral and ibond` on main with
**byte-identical values, dates and URLs** to the ones fetched and quoted above (23000.0 for 2024;
3.11 for the Nov-24 window). This branch was fast-forwarded onto that commit and only the third
row — the one his commit does not carry — was re-applied, so his edit to a protected file stands
exactly as he wrote it.

The third was not in the issue's list. `mortgage_30y_fixed` is a `source: rates` key and A-01 left

`facts/rates.json` — it never rewrites `catalog.yaml`. Verified before editing, not assumed.

## The materiality convention these labels encode

`stale_material` vs `stale_immaterial` is a judgment A-05's rules R1–R5 have to reproduce, so the
convention used here is stated rather than left implicit:

- a **statutory dollar limit that changed** is material — a viewer acting on it contributes the
  wrong amount, and the fix is a number they must retype;
- a **market rate that moved less than ~0.25pp** is immaterial — the advice still stands and only
  the illustration is dated. 6.85 → 6.71 is 0.14pp, hence `stale_immaterial`.

If A-05 draws the line elsewhere, this file is the thing to reconcile against — not the other way
round, because these are Zaeem's labels.

## What the brand check actually is

The issue words proof 3 as a grep. It is not one, and the walkthrough should say so plainly: a
grep against a wordlist of known creator names only ever finds what somebody thought to list.
The implemented check extracts every capitalised proper noun, cashtag, @handle, domain and
acronym in the corpus and fails on anything not in an explicit allowlist — an unknown proper noun
is a failure by default — and it refuses to report PASS until a control fixture with four planted
real references has been flagged. A second test plants a real name into a copy of the actual
corpus and requires the proof to go red, which is what proves the *scan path* can fail rather
than just the fixture. Detail in `docs/proofs/A-02.md`.

## Carried into A-03 / A-04 / A-05

- **`claim_type` vocabulary is new here** and is a superset of `models.Kind`: `statutory_limit`
  and `market_rate` describe facts, while `illustrative`, `historical` and `structural` describe
  claims that must never be resolved against the catalog. A-03's extractor needs all five.
- **`structural` is the category I expect to be hardest.** "You cannot touch the money for twelve
  months" and "you give up three months of interest" are product rules stated as numbers. They
  look exactly like checkable facts and are labeled `skip`. A flag-everything extractor scores
  well on the other four categories and fails here.
- **`unresolved` rows are real IRS figures on purpose.** They are quoted from the same COLA page
  the catalog already cites and are deliberately not catalogued, so the path they exercise is
  "true statement, no entity" rather than "made-up number". A fabricated figure would have tested
  the wrong failure mode.
- **Quote-locatability is enforced, not assumed.** `draft_claims.py` refuses to write when a quote
  is not an exact substring of its source, and proof 2 re-checks all 54 on every run. Editing a
  script without editing the labels now fails loudly instead of silently orphaning ground truth.
- **`evals/claims.jsonl` is protected from now on** (Project Rules), as are `facts/catalog.yaml`
  values. Regenerating with `draft_claims.py` would overwrite Zaeem's labels; after his pass, edit
  the file directly.

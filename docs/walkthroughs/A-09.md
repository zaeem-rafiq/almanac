# A-09 — deploy the app, run the scan while you sleep

## What this issue added

Six files of deploy configuration and CI. **No engine module was touched.** `almanac/**`,
`facts/**`, `evals/**` and `corpus/**` are byte-identical to `bcc70ed`, and `web/app.py` and
`web/static/index.html` — A-08's — were read but never edited.

| File | What it does |
|---|---|
| `api/index.py` | Vercel's Python entrypoint. Re-exports A-08's `web.app:app`, nothing else. |
| `vercel.json` | `maxDuration: 60`, catch-all rewrite to the function, `includeFiles` for the data dirs. |
| `.vercelignore` | Keeps `venv/`, `tests/`, `docs/`, `renders/` and secrets out of the bundle. |
| `requirements.txt` | Pinned deps. The repo had none — both Vercel and the nightly job need one. |
| `.github/workflows/nightly.yml` | The 02:00 CT scan that commits its own output. |
| `.github/workflows/keepalive.yml` | Ten-minute pings across the Sep 8 judging window. |
| `scripts/verify_a09.py` | Closes the pending live proofs once the host exists. |
| `.gitignore` | One hunk, so the nightly commit is possible. Explained below. |

## Three decisions worth the words

**`api/index.py` inserts the repo root on `sys.path` instead of trusting the runtime.** `web/`
has no `__init__.py`, so `web.app` resolves only as a PEP 420 namespace package, which needs the
repository root importable. Vercel does not guarantee the function's cwd is the repo root. Rather
than assume, the entrypoint sets it — and the test for it loads the file with `cwd=/tmp` against
a scratch tree holding A-08's real 15KB app, and asserts `/`, `/api/report` and `/api/lint` are
all present. Importing from the placeholder on `main` would have proven nothing.

**The `.gitignore` hunk is an allow-list, not a hole.** `reports/*` stays ignored; two negations
re-include exactly `reports/latest.json` and `reports/<YYYY-MM-DD>.md`. The date pattern is
literal digit classes, so a stray `reports/notes.md` is not swept in. `write_report` also writes
`latest.md` and a dated `.json` — both remain ignored, because the issue names two files and
committing four would grow the repo nightly for no reader. `git check-ignore` over six paths
confirms the split in both directions.

**The corpus fallback is the path that will actually run.** YouTube's daily quota is exhausted
until midnight Pacific (A-06 spent 8,000 units on five `videos.insert` at 1,600 each), so a
dispatch today on `--source youtube` would 403. `nightly.yml` selects `corpus` whenever
`YT_TOKEN_JSON` is absent. Both branches were exercised locally with the workflow's exact shell,
and the secret's `base64` round-trip was checked byte-for-byte rather than assumed.

The schedule stays nightly on purpose: `captions.download` is 200 units per video, so a
five-video scan is ~1,250 of a 10,000/day budget. Anything more frequent starts failing mid-day.

## What is not proven, and why

Three of the four proofs are PENDING. `docs/proofs/A-09.md` records each with its reason. The
short version, in the order that matters:

1. **The Anthropic account is out of credit** — a live `400` reproduced by running the nightly
   sequence, not inferred. This alone would fail the nightly scan and `/api/lint` on a
   perfectly deployed host, and it also blocks A-05 and A-08.
2. `vercel` is not logged in.
3. No Actions secrets are set.
4. **A-08's app is not on `main`** — `web/app.py` there is still a 57-byte placeholder. Deploying
   before it lands yields a host that 500s on every route.

Items 1–3 are Zaeem's; `docs/A-09-zaeem-checklist.md` has the exact commands. Item 4 is A-08's.

The offline half of proof 4 — keepalive is valid YAML and correctly scheduled — is PASS, and was
made meaningful by two adversarial probes (schedule deleted, cron changed to hourly) that both
had to fail. `maxDuration` was checked the same way. A check that cannot fail is not a check.

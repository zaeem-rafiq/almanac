## What shipped

### The fifth endpoint, and why it exists

The issue lists four. `GET /api/scripts` is a fifth, added for one reason: the textarea must
preload `corpus/scripts/fresh_wrong.md` and swap in `fresh_ok.md`. The alternative was pasting
copies of both files into `index.html`, which forks protected `corpus/**` content into the web
layer where it drifts silently the first time either script changes.
`test_scripts_endpoint_serves_the_real_corpus_files` asserts byte-equality with the files on disk,
so the page cannot show a script the corpus does not contain. Read-only, no keys, no model call.

### The endpoints reuse the CLI's pipeline rather than re-implementing it

`/api/lint` runs `extract.read_source` -> `cli._judged` -> `report.to_row`. A verdict on the page
is the same object `almanac lint` prints. Pasted text is written to a temp `.md` and read back
through the real reader, then `dataclasses.replace`-d to a display `source_id` — so the locators
the page shows are the CLI's locators by construction, not by promise.

`report.VideoReport` carries no `video_id`, so nothing in the report can build a YouTube link.
Rather than reopen `report.py`, `web/app.py` joins `corpus/channel/*/meta.json` at serve time. A
link target is presentation; `report.py` owns the decision shape.

## The write guard — proved, not asserted

**`almanac/youtube.py` contains no `videos.update` code at all.** A-06 shipped read-only; the
module docstring says so and `grep` confirms it. So `/api/apply` has no write path to disable. It
composes the description a human would paste — the video's current `meta.json` description plus the
notes `notes.py` already drafted for rows `judge.py` already ruled `stale_material` — and returns a
`difflib` unified diff.

**It is dry-run unconditionally.** It does not read `ALMANAC_WRITE`, does not import
`almanac.youtube`, and constructs no API client. The Project Rules allow a write only when
`ALMANAC_WRITE=true` AND the channel matches AND the CLI was given `--apply`; a web request cannot
supply `--apply` and there is no way for a visitor to, so there is no configuration under which the
endpoint should write and therefore no branch that could. Proof 3 re-runs it with
`ALMANAC_WRITE=true` and the count stays 0.

**How the zero is made trustworthy.** The counting stub is installed at
`googleapiclient.discovery.build` — the chokepoint *every* YouTube call passes through, including
one a future edit might write without ever touching `almanac.youtube`. Before any zero is believed,
the probe drives that stub by hand and asserts the count reaches 1. A counter wired to the wrong
object reads zero exactly like a clean run.

The stub is installed with `setattr` on the already-imported module object. Not
`monkeypatch.setitem(sys.modules, ...)` — that does not intercept `from pkg.mod import x` once the
real module is imported, because the package attribute wins.

## Design — "almanac page"

Run through the `kole-jain-ui-design` gate. Paper ground (`#faf9f6`), one serif display face, mono
figures with `tabular-nums`, thin rules, chips as ink stamps, no gradients, no shadows, no
cards-in-cards. The serif is a system stack, not a webfont: a CDN font in a single-file page is a
new dependency and a new failure mode for nothing.

**One saturated colour in the document — oxblood — and it is spent entirely on `STALE`.** Five
statuses have to be distinguishable, and the gate's "at most two colours beyond neutrals" and "one
clear focal point" both point the same way: the thing the reader is hunting for gets the ink, and
the other four separate by weight and border treatment. `stale_material` is filled, `stale_immaterial`
is the same hue outlined, `unresolved` is dashed (not determined), `correct` and `skip` are neutral.

**The verdict row is the hero.** Quote @ locator -> `video said` -> **`current`** (largest figure on
the page, oxblood when stale, with the effective date and source host directly beneath) -> `change`
-> chip -> `rule_fired` -> the drafted note. At 390px the figure grid collapses to stacked labelled
lines; measured sideways overflow is **0px** at both widths.

Videos with something flagged are open by default; skipped numbers sit behind a per-video
disclosure so they never compete with the rows that need a human.

## Findings — reported, not fixed

### F-1 · The V4 count in the issue does not match any run this branch produced

The issue specifies the V4 row must show **"5 numbers read, 0 flagged (illustrative)"**. Every run
here produces **19** verdicts for V4 (14 `illustrative`, 4 `other`, 1 `structural`, all
`R2.unjudged_claim_type`). The "5" is from some other run — which is precisely the defect A-05
recorded in D-5: extraction is not reproducible.

Hardcoding `5` would have printed a fabricated number on the page whose entire argument is that it
does not do that. **The row renders the pattern from the data**: `"<N> numbers read, 0 flagged
(<dominant claim_type>)"`, with N and the type computed from the rows the run actually produced.
On this run it reads *"19 numbers read, 0 flagged (illustrative)"*.

`test_v4_count_line_is_read_from_the_run_not_hardcoded` pins the behaviour;
`test_v4_row_states_what_it_read_and_flagged` asserts the rendered string matches the served report
rather than a literal.

**Zaeem's call:** accept the data-driven line, or fix extraction determinism first (ADR-002 D-5) so
a stable number can be quoted.

### F-2 · `notes.py` does not enforce the pin it asks for

`SYSTEM_PROMPT` instructs the model to start the note with `📌`, and `fallback_note()` hard-codes
`"📌 Update: …"`. But `check_note()` validates length, the value string, the year and advice verbs —
**not the pin**. Model-drafted notes on this run open `"📌 This video cites…"` and
`"📌 Correction: …"`, so the literal string `"📌 Update"` appears only on fallbacks.

Found by writing an assertion for `"📌 Update"` and having it fail. The assertion was wrong, not the
code: a test may only assert what the code guarantees. `web.app.NOTE_MARKER` is now the pin alone
and is documented as a UI label rather than an invariant, and the test asserts the real guarantee —
the composed description carries the drafted notes verbatim.

Not fixed here: `notes.py` is A-04's module and adding a pin check to `check_note()` is a behaviour
change to a shipped guard, not a UI concern.

corpus; proof 4 checks 5 video rows, 11 verdict rows, the preloaded script and 0px overflow before
it reports the console count; proof 3 requires a non-empty diff alongside the zero.

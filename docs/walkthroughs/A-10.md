The issue was written at 05:40 UTC on 2026-09-07, before the engine migration, and three of its

**A fourth correction the issue did not flag, and I found by reading the code:** the issue says the
write-back is a *description prepend*. `compose_description()` at `web/app.py:352` builds

documentation-only constraint I did not change the code to match the issue, and the discrepancy is
reported rather than silently reconciled: if the intended product behaviour really is a prepend,
that is a one-line change in `web/app.py` and belongs to a code issue.

## Proof discipline: three of the four checks assert an absence

No broken links, no ungrounded number, no drift from `evals/results.md` are all absence claims, and
the Project Rules say an absence check that has never registered a presence passes vacuously. Each
therefore has a negative control in the transcript, run on a corrupted copy of the README:

| control | the check must FAIL, and did |
|---|---|
| matched rows written as 47 instead of 46 | `UNGROUNDED: 47` |
| `](LICENSE)` → a path that does not exist | `BROKEN: LICENCE-THAT-DOES-NOT-EXIST -> no such file` |
| `**GATE: PASS**` edited inside the pasted block | `the pasted block is NOT byte-identical to evals/results.md` |

Writing the controls found two real bugs in my own checker, both of which would have made it pass
vacuously: `\b\d{4}-\d{2}-\d{2}\b` never matched `2026-09-08` inside `results.json`'s
`2026-09-08T01:53:14+00:00` (the `T` is a word character), and the README's typographic minus
(U+2212) meant `-2.17%` was read as `+2.17` and could not ground against `judge.py`'s `-2.17%`.

### Two deliberate deviations from the proof lines as written

1. The issue's wording is "every numeric claim in README appears in **`evals/results.json` or
   `judge.py` constants**". The README also, correctly, quotes `facts/catalog.yaml` values, the
   `MANUAL_MAX_AGE_DAYS` constant in `catalog.py`, and the reproducibility block — so the checker
   grounds against nine machine-readable artifacts and **names the grounding file for every
   number** (`--verbose`). That is broader than the issue's phrasing, and the proof line says so
   rather than quietly claiming the narrower check.
2. Numbers **inside** the verbatim `results.md` block are grounded by the byte-equality check
   rather than re-parsed. They are a copy of a file `almanac eval` generates; re-grounding them
   would only be checking the copy against itself.
3. `markdown-link-check` is not installed on this machine and installing it means an npm download,
   so `check_links` implements the same contract in-process: local targets must exist on disk,
   `http(s)` targets must answer < 400. The proof line says "link check", not the tool's name.

belongs in the record, not in a silent edit.

## What the README does not claim

The nightly Action is named in the diagram *and* marked a stub in "What's honest", because
`.github/workflows/nightly.yml` is a manual-dispatch no-op. Reproducibility is stated as 9 gate
runs across **two measured states** of `extract.py` — never "9 consecutive identical runs" — and
the pre-migration Anthropic-era runs in ADR-002 are not pooled with anything here. The 8 labelled
rows extraction misses are stated in the README's own voice, not left to the table.

No exception was raised at any point. Both calls returned HTTP 200.

## Hypothesis

The target channel is real and was created today, so `ALMANAC_TEST_CHANNEL_ID` is not a typo.
`mine=true` returns the channels owned by the *authorised identity*, and it returned none —
therefore the identity selected at the consent screen is not the owner of
`UCvt3Yfxa3lq_FyO2gAr3aQQ`.

Two candidate causes, in likelihood order:

1. **A Brand Account was not selected at the chooser.** If the channel sits under a Brand
   Account, consent must be granted *as that Brand Account*. Choosing the underlying personal
   Google account authorises an identity that owns no channel directly, which produces exactly
   this zero-item result.
2. **Two different Google accounts.** The channel was created while signed in as account A; the
   consent screen was completed as account B. Both accounts may legitimately appear in the
   chooser.

This is *not* an API-enablement problem: an unenabled YouTube Data API v3 returns
`accessNotConfigured`, and every call here returned 200.

## Smallest next step
